# 2026-11-08

## 新建：OCS 本地 AI 题库（ocs-answer-llm）

**目标**：给 OCS 网课助手做本地题库服务，填大模型 key 即用，支持识图、联网搜索、Markdown 缓存。

**技术选型**
- 纯 Python 标准库（`http.server` / `urllib` / `tomllib`），零第三方依赖，`python main.py` 直接跑。
- 配置用 TOML（3.11+ 自带 `tomllib`），`config.toml` 内置 7 家 OpenAI 兼容服务商预设。
- 不引入 FastAPI/uvicorn，`ThreadingHTTPServer` 足够，避免安装摩擦。

**关键实现**
- `ocs_answerer/normalize.py`：题干归一化（去题型标记/题号/标点/空白、NFKC）、选项解析（A./A、/(A)/无前缀）。
- `ocs_answerer/bank.py`：Markdown 题库，`## 题干` + `- 字段: 值` 格式；精确 key + difflib 模糊匹配；**同题干换选项不复用旧答案**（选项相似度校验）。
- `ocs_answerer/solver.py`：缓存 → 模型 → 判断题语义兜底 → 时事联网 → 二次作答 → 回写。单题 55s 预算（OCS 侧 60s），同题并发合并。
- `ocs_answerer/vision.py`：本地/URL/dataURL 三种图片来源，转 data URL 交给视觉模型。
- `ocs_answerer/websearch.py`：bing（免 key，实测可用）、duckduckgo、tavily/serper/bocha。
- `ocs_answerer/server.py`：`/api/search`、`/api/ocs-config`、`/api/stats`、`/api/reload`，带浅色状态页和复制按钮。

**核对过的 OCS 契约（4.0 源码）**
- 题库配置 `data` 里的 `{handler}` 只在 **POST** 下生效；GET 会把对象变成 "[object Object]"。
- `AnswerWrapperHandlerConfig.timeout_seconds = 60`。
- 多选题答案用 `#` 分隔；`splitAnswer` 先尝试 JSON 数组。
- `resolveSingle` 会先做归一化精确匹配（答案⊇选项），再相似度，再纯 ABCD 兜底 → 因此**回传完整选项原文**最稳。
- 判断题是 `clearString(removeRedundant(x))` 精确相等，必须是选项原文（"A. 对"）而不是字母。

**测试**：`tests/test_e2e.py`（假模型服务跑全链路，17 例）、`tests/test_ocs_compat.py`（把 OCS 匹配算法移植成 Python 验证答案格式，9 例）。共 26 例全绿。

**未做**：GUI（用户明确不需要）、截图 OCR（图片由视觉模型直接识别）。

## 1.1.0 修复（用户反馈两处）

**问题一：OCS 提示「当前题库配置暂不支持图片、公式等题目处理」**

浅克隆 ocsjs 5.0 分支确认判定逻辑在 `packages/scripts/src/utils/answerer-env.ts`：

```ts
isAnswererWrapperSupportImageOptimize(wrapper):
  method 必须 post
  data 里任一字符串包含 ${images}/${suggestion_title}/${suggestion_options}
  或任一 handler 源码匹配 /(^|[^\w$])(images|suggestion_title|suggestion_options)(?![\w$])/
```

1.0 的配置靠 `image` handler 抓 DOM，handler 里没有这些词 → 被判为不支持。
5.0 env 新增：`images: string[]`（PNG data URL）、`suggestion_title`、`suggestion_options`（图片 URL 换成 ` [图片N] `），原始 title/options 不再被覆盖。

改法：data 改成
- `title`: handler `return (env) => (env.suggestion_title || env.title || '')`
- `options`: handler `return (env) => (env.suggestion_options || env.options || '')`
- `type`: `${type}`
- `images`: handler 优先返回 `env.images`，为空才退回 DOM 抓取

这样 5.x 走 base64（免下载、免防盗链），4.x 仍能回退。纯图片题题干是 ` [图片1] `，`_prepare_question` 去掉占位符后为空 → 改用图片指纹做 key，展示名 `[图片题] <hash12>`。

**问题二：多选题命中单选题缓存**

`Bank.lookup` 原来只比对题干 + 选项，不看题型。改为 `qtype` 参与过滤（任一方为空则放行，兼容手写条目），`Bank.save` 的更新匹配也加题型，否则两种题型会互相覆盖、反复改文件。`BankEntry.qtype` 默认改成空串，`to_markdown` 仅在非空时写 `- 类型:`。

**测试**：新增 type 隔离、纯图片题 key、图片题优化检测（移植 OCS 判定函数）等用例，共 31 例通过。
